Radar Mercado Público — instalación

Seis pasos, ~15 minutos, una sola vez. Después funciona solo todos los días hábiles.
ya está

0Tu ticket de la API

Ya lo tienes, llegó a tu correo. Lo vas a necesitar en el paso 4:

MP_TICKET21B47C7F-B406-4217-8CAF-5E2EAE2D5D10
Esto es una llave de acceso: no la publiques ni la subas a un repositorio público. En el paso 4 va en un campo de GitHub que la guarda encriptada.
3 min

1Cuenta en GitHub

Si no tienes, créala gratis en github.com/signup. Con el correo y una contraseña basta; el plan gratis alcanza y sobra para esto.

Si ya tienes cuenta, solo inicia sesión.

2 min

2Crear el repositorio

  1. Anda a github.com/new
  2. Repository name: radar-mp
  3. Marca Private (importante: ahí va tu ticket)
  4. No marques nada más. Clic en Create repository
4 min

3Subir los archivos

  1. Descomprime el archivo radar-mercadopublico.zip que te envié. Queda una carpeta radar-mp adentro.
  2. En tu repositorio recién creado, clic en uploading an existing file (el enlace azul en medio de la página).
  3. Abre la carpeta radar-mp, selecciona todo lo que hay adentro (Ctrl+A) y arrástralo a la zona de subida del navegador.
  4. Abajo, clic en Commit changes.
Fíjate que arriba, en la lista de archivos, aparezca la carpeta .github. Si no aparece, tu explorador está ocultando las carpetas que empiezan con punto: actívalas en Ver → Elementos ocultos (Windows) o Cmd+Shift+. (Mac) y vuelve a arrastrar. Sin esa carpeta el bot no se programa solo.
2 min

4Guardar el ticket como secreto

  1. En tu repositorio: pestaña Settings (arriba a la derecha).
  2. Menú izquierdo: Secrets and variables → Actions.
  3. Botón verde New repository secret.
  4. Name: MP_TICKET — escríbelo exactamente así, en mayúsculas.
  5. Secret: pega el ticket del paso 0.
  6. Add secret.
GitHub lo encripta y nunca más lo muestra. Si te equivocas, lo borras y lo creas de nuevo.
2 min

5Encender el bot y probarlo

  1. Pestaña Actions. Si sale un aviso, clic en I understand my workflows, go ahead and enable them.
  2. En la lista de la izquierda, clic en Radar Mercado Publico.
  3. A la derecha: Run workflow → botón verde Run workflow.
  4. Espera 2 a 4 minutos y recarga. Un ✅ verde significa que corrió bien.

Desde ahí en adelante corre solo, de lunes a viernes en la mañana.

1 min

6Ver el informe

Vuelve a la pestaña Code del repositorio y entra a la carpeta data. Ahí van a estar:

  • informe.html — el listado del día, para abrir en el navegador
  • latest.json — los mismos datos, para que yo los lea
  • historial/ — una copia por cada día, se va acumulando

Después pásame la dirección de tu repositorio (algo como github.com/tunombre/radar-mp) y dejo programado el resumen diario: cada mañana leo el resultado, reviso las bases de cada licitación y te digo cuáles vale la pena postular y cuáles no.

Si algo se rompe

El paso 5 sale con ✗ rojo: entra a la corrida, abre el paso «Ejecutar radar» y mira el mensaje. Si dice Ticket no válido, el secreto quedó mal escrito o con espacios: bórralo y créalo de nuevo. Si dice que no devolvió activas, la API de Mercado Público estaba caída — pasa seguido, se arregla sola al día siguiente.

Te llega un correo de GitHub diciendo que deshabilitó el workflow por inactividad: GitHub apaga las tareas programadas en repositorios sin actividad por 60 días. Entra a Actions y clic en Enable workflow. Se vuelve a activar al toque.

Llegan muchas licitaciones que no sirven, o muy pocas: avísame y ajustamos los pesos del filtro. Es un archivo de texto, se cambia en un minuto.

El bot no gasta nada: GitHub Actions es gratis en este volumen y la API de Mercado Público también. Tu ticket permite 10.000 consultas al día y el radar usa entre 50 y 150.
